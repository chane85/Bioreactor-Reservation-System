## What Was Built

### 1. Month/Day Divider Line Alignment
**Problem:** Vertical divider lines between months were misaligned across the header rows and the Gantt body.  
**Fix in `Gantt.jsx`:**
- Month spans: `boxSizing: 'border-box'` + `borderLeft: '3px solid #333'` (si > 0 only)
- Day cells: `boxSizing: 'border-box'` + `boxShadow: 'inset 3px 0 0 #333'` on day-1 cells
- Grid body: absolute-positioned 3px-wide divs at `left: i * DAY_WIDTH` for month boundaries

### 2. Hover Date Tooltip

### 5. Multi-Bar Selection and Drag
**Behaviour:**
- **Click** a bar → select it (blue border + glow), deselects others
- **Ctrl+Click** → toggle bar in/out of selection
- **Click empty grid** → clear all selections
- **Drag a selected bar** → all selected bars move together by the same number of days
- **Drag an unselected bar** → selects only that bar, drags it normally (existing behaviour)
- **Vertical row-shift disabled** during multi-drag (horizontal date shift only)
- **Boundary clamping:** all bars stop when any one would exit the view

**Key code in `Gantt.jsx`:**
- `selectedIds` state (Set of booking_ids)
- `selectedIdsRef` + `bookingsRef` — refs so closures always see latest values
- Click vs drag distinguished by mouse travel distance (< 4px = click)
- `onMoveMultiple(moves)` prop for batch backend updates

**In `App.jsx`:**
```javascript
const handleMoveMultiple = useCallback(async (moves) => {
  for (const m of moves) {
    d = await api.moveBooking(user, m.bookingId, m.newReactorId, m.newStart, m.newEnd);
  }
  const df = await api.getDiff(); setDiff(df);
}, [user]);
```

### 6. Overlap Prevention
**Behaviour:** If a dragged bar (single or multi) is dropped in a position where an existing bar on the same reactor **completely contains** its date range, the drop is rejected — bar snaps back and a red toast appears: `"다른 예약과 겹칩니다 — 이동이 취소되었습니다"`.  
**Partial overlap is allowed** (both bars still partially visible).

**Condition that blocks the drop:**
```javascript
bk.start <= m.newStart && bk.end >= m.newEnd
// existing bar fully covers the dropped bar
```

### 7. Ambr Booking ID Uniqueness Fix
**Problem:** All vessels in the same Ambr step shared the same `booking_id`, so deleting one bar deleted all 12.  
**Fix in `pages/3_Reservation.py`:**
```python
# Before (bug):
for unit in item['vessels']:
    "booking_id": f"AMBR_{bid}_{item['step_idx']}"

# After (fixed):
for v_idx, unit in enumerate(item['vessels']):
    "booking_id": f"AMBR_{bid}_{item['step_idx']}_{v_idx}"
```
Each vessel now gets a unique ID. **Note:** Existing bookings made before this fix still have duplicate IDs — those must be re-booked.

## Critical Notes

### DATA_DIR — Local vs Server
- **Local** `_sandbox_server.py` has `env={**os.environ, 'DATA_DIR': _THIS_DIR}` → backend finds CSV in `Bioreactor_1.7_ori - 복사본/`
- **GitHub/Server** `_sandbox_server.py` does NOT have this line → backend falls back to `Bioreactor_5/` default in `sandbox_v2/backend/utils.py`
- **Never push the local DATA_DIR line to GitHub** — it overrides `Bioreactor_5/` and breaks the server

### How to Rebuild and Deploy
1. Make changes to `sandbox_v2/frontend/src/App.jsx` or `Gantt.jsx`
2. Run `npm run build` in `sandbox_v2/frontend/`
3. Restart Streamlit to pick up new `dist/`

### Port Numbers (never change)
- Streamlit: `8560`
- FastAPI backend: `8561`

### Version Sync
`_API_VERSION` in `sandbox_v2/backend/main.py` must always match `_REQUIRED_VERSION` in `_sandbox_server.py`. Both are currently `10`.
