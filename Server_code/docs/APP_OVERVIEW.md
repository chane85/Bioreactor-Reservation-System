# 배양기 예약 시스템 — 기능 개요

> 처음 읽는 개발자를 위한 요약본이다. 주요 기능과 핵심 로직만 담았다.
> 세부 규칙, 코드 위치, 알려진 버그 전체 목록은 [`RESERVATION_LOGIC.md`](RESERVATION_LOGIC.md)에 있다.

---

## 1. 이 앱은 무엇을 하나

세포배양 연구실의 **배양기(2L–200L, Wave)와 Ambr 시스템(Ambr250, Ambr15)의 사용 일정을 예약하고 관리**하는 웹앱이다.

- 사용자는 제품(예: `SB27`)의 seed train(N-4 → N)에 필요한 배양기를 기간 단위로 예약한다.
- 관리자는 고장·Calibration 기간을 막고, 예약을 수정하며, 백업에서 복원한다.
- 예약 데이터로 **설비 가동률**과 **본배양(N stage) 비용**을 계산한다.

현재 구현은 Python **Streamlit** 앱과 드래그 편집용 **FastAPI + React** 샌드박스로 되어 있다. 데이터는 **CSV 파일 하나**에 저장된다.

## 3. 핵심 데이터

**예약 1건 = 설비 1대의 한 기간 점유.** 컬럼은 다음과 같다.

```
booking_id, reactor_id, user(SME), project(제품), stage, method, start, end, vessels_used(Ambr15만)
```

**설비 목록**은 DB가 아니라 코드 상수에서 생성한다. 총 306대다.
- 배양기: `{층}-{scale}-{번호}` (예: `6층-2L-05`, Perfusion 전용은 `6층-2L-P1`)
- Ambr250: vessel 단위로 예약 (예: `Ambr250-EQ00005350-01`)
- Ambr15: station 단위로 예약, 1 station = 12 vessel (예: `Ambr15-EQ00000257-S1`)

---

## 4. 가장 중요한 규칙: 날짜와 충돌

1. **저장:** `end = start + 배양일수`. 예를 들어 6/1 시작 4일 배양은 `end = 6/5`로 저장된다.
2. **충돌 판정:** `기존.start < 신규.end AND 기존.end > 신규.start`.
   앞 예약의 종료일에 다음 예약을 시작할 수 있다. 즉 **같은 날 교대를 허용**한다.
3. **표시:** Gantt는 종료일 칸까지 칠한다. 4일 배양이 5칸으로 보인다.

이 세 규칙이 예약, 블록, 비용, 가동률 전체의 기준이다. 새 플랫폼에서도 이 해석을 그대로 따라야 기존 데이터의 충돌 판정 결과가 바뀌지 않는다.

## 5. 주요 기능과 로직

### 5.1 배양기 예약 위저드

seed train 전체(N-4 → N)를 한 번에 예약한다.

- **입력:** 제품명, SME, 기준일, 그리고 stage별로 scale, 공정(method), 배양일수, 배양기 수.
- **일정 계산:** stage를 순서대로 이어 붙인다. 다음 stage는 이전 stage의 종료일에 시작한다.
  - **Forward:** N-4 시작일을 기준으로 앞에서부터 계산한다.
  - **Reverse:** N 시작일을 기준으로 거꾸로 계산한다. 결과가 오늘 이전으로 가면 오류를 낸다.
- **후보 선정:** scale이 같은 설비 중 그 기간에 비어 있는 것을 층 → scale → 번호 순으로 보여준다. N-1을 Perfusion으로 고르면 Perfusion 전용 배양기만 후보가 된다.
- **확정:** stage마다 정확히 필요한 대수를 선택하면 설비당 1행씩 저장한다.

### 5.2 Ambr 예약

- Ambr250은 vessel 수, Ambr15는 station 수로 예약한다. stage는 항상 `N`이다.
- 한 step에서는 **장비(EQ) 1대 안에서만** vessel이나 station을 고른다.
- Ambr15는 station마다 실제 사용 vessel 수(1–12)를 입력할 수 있고, 이 값이 비용 계산에 쓰인다.

### 5.3 사용 불가 블록 (관리자)

| 종류 | 대상 | 동작 |
|---|---|---|
| 설비 블록 (`BLOCK_`) | 배양기, Ambr250 vessel, Ambr15 station | 그 기간의 예약을 막는다. 겹치는 기존 예약은 **자동 백업 후 삭제**한다 |
| vessel 블록 (`VBLOCK_`) | Ambr15 station 안의 개별 vessel | 예약을 막지 않는다. 비용 계산에서 해당 vessel을 빼는 용도다 |

블록은 `project = 수리중`으로 저장되어 Gantt에 회색으로 표시된다.

### 5.4 시뮬레이션 샌드박스

여러 예약을 Gantt에서 직접 옮겨 보고, 확정할 때만 반영하는 기능이다.

1. **잠금 획득:** 한 번에 한 사람만 편집한다. 30분 동안 변경이 없으면 잠금이 자동으로 풀린다.
2. **사본 편집:** 실제 데이터를 복사해 그 위에서 드래그 이동, 기간 조정, 삭제, 추가, 되돌리기(최대 50단계)를 한다. 편집 중에는 겹침이 허용된다.
3. **적용:** editor 또는 admin의 비밀번호를 다시 입력해야 한다. 서버는 다음 두 가지를 검사한다.
   - 변경한 예약이 **현재 실제 데이터**와 겹치는지 (편집 도중 다른 사람이 추가한 예약까지 반영)
   - 변경한 예약끼리 서로 겹치는지
   하나라도 충돌하면 아무것도 저장하지 않는다. 통과하면 백업한 뒤 변경분만 반영하고 감사 로그를 남긴다.

### 5.5 비용 산출

```
대상: stage == N 이고 scale ∈ {Ambr15, Ambr250, 2L, 200L}
비용 = Σ (vessel 수 × 단가[scale, method])
vessel 수: Ambr15 station = vessels_used(기본 12), 그 외 = 1
```
- 단가는 vessel 1개당 KRW이며 코드에 하드코딩되어 있다.
- 기간별 비용은 그 기간과 하루라도 겹치는 예약의 **전체 비용**을 합산한다. 일할 계산은 하지 않는다.

### 5.6 홈 대시보드

- **가동률:** (예약된 설비·일수) ÷ (설비 수 × 월 일수). 이번 달과 다음 달을 보여준다. 블록 기간도 사용으로 계산한다.
- **일정 알림:** 오늘, 내일, 지정한 날에 시작하는 예약의 수와 목록.
- **Gantt:** 제품별 색상, 주말·한국 공휴일 표시, 오늘 선.

### 5.7 관리자 기타

- 예약 표에서 직접 편집하거나 삭제한다. 이때 충돌 검사는 하지 않는다.
- 자동 백업은 최신 10개를 보관하고, 그중 하나로 복원할 수 있다. CSV 내보내기와 가져오기도 지원한다.
- Excel Gantt에서 만든 CSV를 일괄 Import한다. 모드는 추가 / 전체 교체, 충돌 시 건너뛰기 / 덮어쓰기다.
- 감사 로그를 조회한다.

## 7. 이전 전에 꼭 합의할 5가지

현재 코드에 의도와 다르게 보이는 동작이 있다. 새 플랫폼에서 그대로 옮길지 고칠지 업무 담당자와 먼저 정해야 한다. 전체 20개 항목은 상세 문서 14장에 있다.

1. **동시 저장 보호가 없다.** CSV 파일 전체를 덮어쓰는 방식이라 동시에 저장하면 한쪽 변경이 사라진다. 저장 직전에 충돌을 다시 검사하지도 않는다. → DB와 트랜잭션으로 해결해야 한다.
2. **날짜 구간 해석이 기능마다 다르다.** 충돌 판정은 종료일을 제외하지만, 블록 삭제·비용·가동률은 종료일을 포함한다. 그래서 블록을 만들 때 인접한 예약이 함께 삭제될 수 있다.
3. **위저드 기본 옵션이 빈 배양기를 숨긴다.** 기본 상태에서는 이후에 예약이 하나라도 있는 배양기가 후보에서 빠진다.
4. **비용 규칙을 확인해야 한다.** 일할 계산이 없고, 5L·10L·50L·Wave는 비용에서 빠지며, Ambr15 vessel 블록이 실제로는 차감되지 않는다.
5. **사용자 식별과 일부 화면이 보호되지 않는다.** 샌드박스는 사용자를 자유 텍스트로 식별하고, 비용 페이지에는 로그인 검사가 없다.
